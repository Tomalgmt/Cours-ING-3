PRIORITÉ ET CRITICITÉ
L'ordre va du risque réel le plus important au moins important dans le contexte
observé : VM derrière un NAT, SSH redirigé uniquement depuis 127.0.0.1:2222 du PC.
Élevée : accès root facilité ou protection majeure retirée.
Moyenne : risque significatif, conditionné par l'accès ou une autre faiblesse.
Faible : risque secondaire ou prérequis importants.
Informative : divulgation limitée sans accès direct.
Un contrôle noté n'est pas automatiquement une vulnérabilité grave.
Les points à vérifier sont explicitement distingués des défauts constatés.
Les lignes citées correspondent à la copie du script dont l'empreinte figure
ci-dessus. La criticité n'est ni un nombre de points ni un score CVSS.

CONTRAINTE ÉLIMINATOIRE DU BARÈME
Le script attend une réponse contenant OK à http://127.0.0.1:8080/health
et contrôle nginx actif et activé au démarrage. Un service métier indisponible
entraîne un plafond annoncé de 08/20. Aucun échec de ce service n'est affirmé
ici et aucun test de disponibilité n'a été lancé pendant ce filtrage.

01. Droits sudo donnant un accès root sans mot de passe
Criticité : Élevée
Référence de l'audit : Complément au contrôle sudo de la section Authentication

Constatation factuelle :
/etc/sudoers.d/99-laxiste autorise stagiaire : NOPASSWD: ALL ; bob : NOPASSWD: /bin/bash ; alice : NOPASSWD: /usr/bin/find. Les droits effectifs ont été confirmés par sudo -l pour chaque compte. Les trois comptes disposent d'un mot de passe (statut P).

Menace associée :
Une personne contrôlant une session de l'un de ces comptes peut exécuter des commandes root ; find peut lancer un autre programme. Compromission totale de la VM, modification des données et des traces.

Argument de criticité :
Impact maximal et chemin d'élévation direct, sans vulnérabilité logicielle nécessaire. L'accès préalable à l'un des comptes reste requis ; aucune compromission à distance sans authentification n'a été démontrée. C'est la première correction à traiter.

Lien avec le script de notation :
- Ligne 65 : Compte stagiaire supprime ou verrouille.
- Ligne 72 : Plus aucune regle NOPASSWD: ALL.
- Ligne 73 : Fichier /etc/sudoers.d/99-laxiste supprime.

02. Mot de passe faible d'un compte administrateur et SSH par mot de passe
Criticité : Élevée
Référence de l'audit : AUTH-9262 ; SSH-7408 ; complément de connexion

Constatation factuelle :
La connexion autorisée de moutsss a réussi avec un secret de quatre chiffres, non reproduit ici. Ce compte possède des droits sudo complets. Les vérifications initiales indiquent PasswordAuthentication yes, MaxAuthTries 10 et LoginGraceTime 300 ; Lynis ne trouve pas de module dédié de qualité des mots de passe. L'absence de pam_faillock/pam_tally2 n'a pas été vérifiée : elle ne constitue pas un défaut confirmé dans cette fiche.

Menace associée :
Devinette du mot de passe, prise du compte puis élévation root avec le même secret.

Argument de criticité :
Le secret est effectivement faible, pas seulement une politique théorique. Le NAT et la redirection sur la boucle locale Windows limitent fortement les attaquants pouvant joindre SSH ; ils n'améliorent pas le secret lui-même. MaxAuthTries est une limite par connexion, pas un verrouillage global.

Lien avec le script de notation :
- Ligne 68 : Module de robustesse des mots de passe present (pwquality/cracklib).
- Ligne 79 : Authentification par mot de passe desactivee.
- Ligne 80 : MaxAuthTries <= 4.
- Ligne 81 : LoginGraceTime <= 60.

06. Filtrage local non démontré malgré l'indicateur Lynis
Criticité : Moyenne
Référence de l'audit : Section Software: firewalls ; complément direct

Constatation factuelle :
Lynis affiche ACTIVE. Pourtant nft list ruleset ne renvoie aucune règle ; les commandes iptables, ip6tables et leurs variantes legacy ne sont pas disponibles. Des services écoutent sur toutes les adresses : SSH, NFS/RPC et nginx.

Argument de criticité :

Lien avec le script de notation :
- Ligne 96 : Un pare-feu est actif (nftables ou ufw).
- Ligne 97 : Politique par defaut restrictive en entree.
- Ligne 98 : Le pare-feu survit au redemarrage (unite activee).

Lien avec le script de notation :

LIMITES DU FILTRAGE
Les contrôles du script sans constat correspondant dans l'audit initial ne sont
pas ajoutés comme de nouveaux problèmes. En particulier, l'absence d'une fiche
sur les permissions /etc/shadow, /srv/metier, /opt/scripts ou sur find-suid
ne signifie pas que ces contrôles sont conformes. Le document n'est donc pas
un relevé exhaustif PASS/FAIL et ne permet pas de calculer une note.

Quelques différences entre libellés et tests doivent être conservées en tête :
- Le test d'expiration nommé « alice, bob » interroge seulement alice.
- Les tests rpcbind/avahi/NFS vérifient l'activité, pas réellement la désactivation
  au démarrage, malgré certains libellés.
- Le test de persistance sysctl recherche une ligne ASLR=2 dans un fichier :
  il ne vérifie pas tous les paramètres après un redémarrage.
- La présence de textes PAM ou sudo dans des fichiers ne prouve pas, à elle seule,
  qu'ils sont actifs et efficaces.
- La simulation APT dépend de la fraîcheur des index et de son filtre textuel.
Ces limites n'autorisent pas à déclarer une protection efficace sur le seul
résultat d'un test textuel.

Aucune commande de correction, installation de paquet, modification de service,
de compte, de permission système ou de paramètre de sécurité n'a été exécutée.
