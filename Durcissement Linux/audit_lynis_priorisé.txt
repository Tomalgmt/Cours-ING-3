01. Droits sudo donnant un accès root sans mot de passe
Criticité attribuée : Élevée
Références : Complément au contrôle sudo de la section Authentication

Constatation factuelle :
/etc/sudoers.d/99-laxiste autorise stagiaire : NOPASSWD: ALL ; bob : NOPASSWD: /bin/bash ; alice : NOPASSWD: /usr/bin/find. Les droits effectifs ont été confirmés par sudo -l pour chaque compte. Les trois comptes disposent d'un mot de passe (statut P).

Menace associée :
Une personne contrôlant une session de l'un de ces comptes peut exécuter des commandes root ; find peut lancer un autre programme. Compromission totale de la VM, modification des données et des traces.

Argument de criticité :
Impact maximal et chemin d'élévation direct, sans vulnérabilité logicielle nécessaire. L'accès préalable à l'un des comptes reste requis ; aucune compromission à distance sans authentification n'a été démontrée. C'est la première correction à traiter.

Orientation de correction (non exécutée) :
Retirer les autorisations générales et les programmes permettant un shell ; définir uniquement les opérations administratives nécessaires.

02. Mot de passe faible d'un compte administrateur et SSH par mot de passe
Criticité attribuée : Élevée
Références : AUTH-9262 ; DEB-0880 ; SSH-7408 ; complément de connexion

Constatation factuelle :
L'authentification autorisée de moutsss a réussi avec un mot de passe de quatre chiffres fourni par l'utilisateur, non reproduit ici. sudo -l lui accorde (ALL : ALL) ALL. sshd -T confirme PasswordAuthentication yes, MaxAuthTries 10 et LoginGraceTime 300. Lynis ne trouve ni module dédié de qualité des mots de passe ni fail2ban.

Menace associée :
Devinette du mot de passe, prise du compte puis élévation root avec le même secret.

Argument de criticité :
Le secret est effectivement faible, pas seulement une politique théorique. Le NAT et la redirection sur la boucle locale Windows limitent fortement les attaquants pouvant joindre SSH ; ils n'améliorent pas le secret lui-même. MaxAuthTries est une limite par connexion, pas un verrouillage global.

Orientation de correction (non exécutée) :
Remplacer le secret par une phrase robuste ; préparer et tester les clés SSH avant toute désactivation des mots de passe. Limiter ensuite les tentatives selon le besoin.

22. Gestion des core dumps à préciser
Criticité attribuée : Faible
Références : KRNL-5820 ; KRNL-6000 : fs.suid_dumpable, kernel.core_uses_pid

Constatation factuelle :
Lynis trouve une configuration par défaut. En direct : fs.suid_dumpable=2, kernel.core_pattern=core, kernel.core_uses_pid=0.

29. Version Lynis ancienne et couverture partielle du scan
Criticité attribuée : Faible
Références : LYNIS ; HTTP-6624:1

Constatation factuelle :
Rapport Lynis 3.0.8 : avertissement d'ancienneté, exception d'analyse de configuration Apache ; test des paquets actualisables SKIPPED et avertissement pgrep. Trois tests signalent seulement une durée longue.

Menace associée :
Des défauts peuvent ne pas être détectés ou certaines recommandations peuvent être mal adaptées.

Argument de criticité :
Il s'agit d'une limite de l'audit, pas d'une vulnérabilité du système prouvée. Les durées longues ne sont pas des incidents de sécurité.

Orientation de correction (non exécutée) :
Employer une version maintenue et compléter les contrôles concernés ; conserver ce rapport comme état initial.

30. Hachage des mots de passe supposé insuffisant
Criticité attribuée : Non démontrée
Références : AUTH-9229 ; AUTH-9230

Constatation factuelle :
Lynis recommande de fixer les rounds ; PAM utilise pam_unix.so obscure yescrypt. login.defs mentionne SHA512, mais cette ligne seule ne décrit pas le hachage effectué par PAM.

Menace associée :
Si des empreintes anciennes ou un coût réellement faible existaient, une copie des empreintes pourrait faciliter une attaque hors ligne.

Argument de criticité :
Aucun algorithme faible ni coût inadéquat n'a été établi. L'absence de rounds explicites n'est pas l'absence de hachage ; des paramètres par défaut existent. Les empreintes n'ont pas été extraites.

Orientation de correction (non exécutée) :
Vérifier les algorithmes et coûts effectifs avant de modifier PAM ; ne pas dégrader yescrypt pour satisfaire une suggestion générique.

31. Modules de protection Apache absents
Criticité attribuée : Non démontrée
Références : HTTP-6640 ; HTTP-6643

Constatation factuelle :
Lynis trouve des éléments Apache mais n'analyse pas correctement sa configuration. apache2 est inactif ; l'écoute HTTP observée appartient à nginx sur 8080.

Menace associée :
Attaques web ou déni de service si une application Apache exposée existait.

Argument de criticité :
Aucun service Apache exposé démontré. Installer mod_evasive ou ModSecurity pour Apache ne protège pas automatiquement nginx.

Orientation de correction (non exécutée) :
Revoir ces recommandations uniquement si Apache est réellement utilisé.

32. Fichiers supprimés encore ouverts
Criticité attribuée : Non démontrée
Références : LOGG-2190

Constatation factuelle :
Lynis signale FILES FOUND. L'échantillon lsof +L1 montre surtout des memfd de PipeWire/GNOME et des métadonnées utilisateur supprimées.

Menace associée :
Dans d'autres cas : occupation de disque persistante ou processus conservant une ancienne bibliothèque.

Argument de criticité :
Les memfd observés sont compatibles avec un usage normal de mémoire partagée. Aucun gros journal bloqué ni ancienne bibliothèque vulnérable n'est établi ; l'échantillon n'est pas exhaustif.

Orientation de correction (non exécutée) :
Examiner les entrées inhabituelles avant de redémarrer des processus.


============================================================================
33. Port SSH standard
Criticité attribuée : Informative
Références : SSH-7408 : Port

Constatation factuelle :
SSH écoute sur 22 dans la VM ; VirtualBox le redirige depuis 127.0.0.1:2222 sur Windows.

Menace associée :
Le port standard facilite la découverte par des scans lorsqu'il est accessible.

Argument de criticité :
Le numéro de port n'est pas une vulnérabilité. Le changer ne corrige ni un mot de passe faible ni les droits sudo.

Orientation de correction (non exécutée) :
Aucune correction de sécurité nécessaire pour ce seul point.

34. Bannières jugées insuffisantes
Criticité attribuée : Informative
Références : BANN-7126 ; BANN-7130

Constatation factuelle :
Lynis marque /etc/issue et /etc/issue.net WEAK.

Menace associée :
Information ou rappel des conditions d'accès insuffisant pour les utilisateurs.

Argument de criticité :
Une bannière n'empêche pas une intrusion. Le scan ne démontre pas ici de fuite technique critique ; cette observation relève principalement de la politique d'usage.

Orientation de correction (non exécutée) :
Adapter le texte au contexte de l'établissement si demandé.

LIMITES
Ce document est une priorisation argumentée, pas une certification de sécurité.
L'absence d'une suggestion ne prouve pas l'absence d'un défaut. Les règles SSH
conditionnelles, ACL de tous les fichiers, applications web, état des correctifs
et tous les mécanismes de filtrage n'ont pas fait l'objet d'un audit exhaustif.
Ne pas appliquer mécaniquement toutes les valeurs du profil Lynis : elles
peuvent être inutiles ou casser une fonction légitime. Réévaluer après correction
des droits sudo, des secrets faibles et de l'ASLR, en conservant un accès de secours.
